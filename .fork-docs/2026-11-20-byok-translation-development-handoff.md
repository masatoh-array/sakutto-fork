## 変更しない境界

- 個人用の fork。汎用フレームワーク化や無関係な改修はしない。本家との将来の差分を小さく保つ。作業・公開先は `dot/byok-translation`。main など他ブランチを更新せず、アップストリームの取り込みは別作業とする。
- 公開リポジトリに実キー、トークン、秘密を含む URL、個人・組織の情報、実ページ本文やログを追加しない。この作業の確認に社内資料や既存資格情報を取りに行かず、対象ソースと合成データで検証する。コミット前にステージ済み差分、新規ファイル、対象の履歴を確認する。
- OpenAI キーをページの DOM、Web Storage、コンテンツスクリプト、通常設定、同期ストレージ、キャッシュに入れない。拡張機能専用の `chrome.storage.session` を `TRUSTED_CONTEXTS` に限定し、設定失敗時はキーを取り出さない。認証ヘッダーを付ける相手はバックグラウンドから固定の `https://api.openai.com/v1/responses` のみ。クラウド方式は原文・設定に応じた文脈や用語集を送るので、社外送信できないページではローカル方式を使う。
- 訳文はキャッシュに平文で残る。原文そのものやキーは保存しないが、キャッシュキーのハッシュは暗号化ではない。オリジンはブラウザが与える送信元から判定し、確認できなければキャッシュを使わない。閲覧ページ B に A の訳文・サイト用語集を渡す経路を増やさない。既存の明示的な共通用語集やローカル側ストレージ仕様を今回の対象に広げない。
- ブラウザ再起動や拡張機能の再読み込みで OpenAI キーは消える。キャッシュは残り、再利用にもキーの再入力と接続権限が必要。キー削除やローカル切替はキャッシュ消去ではない。設定の翻訳キャッシュ消去はローカル用と OpenAI 用の両方を消し、実行中の古い結果による再保存も防ぐ。
- Copilot の組織内 grounding は、Web 検索を無効化しても止まるとは確認できていない。ページ原文に埋め込まれた指示の影響で組織内情報が回答に混ざる恐れがある。プロンプトだけを安全対策とみなさず、ページへの自動入力・出力、コンテンツスクリプトへの応答、HTML 描画につながない。認証トークンは専用画面のメモリのみに保持する。

## 再開時の順序

1. `git status --short --branch` と対象リモートの先端を確認する。既存の未コミット作業は温存する。実装差分は `git diff 3dd7b9f..889233b`。実装の経緯は `5e365b1`（OpenAI 初期対応）、`b79e8ca`（分離と資格情報保護）、`f6d3621`（パッケージ監査）、`889233b`（小バッチ・永続キャッシュ）の順にたどれる。
2. OpenAI は [engine.ts](../src/engine/openai/engine.ts) → [cache.ts](../src/engine/openai/cache.ts)・[credentials.ts](../src/engine/openai/credentials.ts) → [engine-client.ts](../src/background/engine-client.ts)・[translation-broker.ts](../src/background/translation-broker.ts) → [設定 UI](../src/ui/CloudTranslationSettings.svelte) を確認する。Copilot は [client.ts](../src/engine/copilot/client.ts) と [専用画面](../src/entrypoints/copilot/App.svelte) から読む。
3. Node.js 24 以上と `package.json` 指定の pnpm を使い、`pnpm typecheck`、`pnpm lint`、`pnpm test` を実行する。通常の `pnpm build`・`pnpm zip` には検証済み wllama 成果物が必要。取得元・確認方法は [既存 BYOK メモ](../docs/BYOK.md) の正式パッケージ節を参照。モックビルドを実用配布物として扱わない。
4. **次に確認するのは OpenAI の実ブラウザ動作。** 利用者がキーを設定画面から自分で入力し、機密を含まない同じページで初回と再翻訳の時間・API 呼び出し数・訳語を比較する。Chrome 再起動後はキーを再入力し、同じまとまりの翻訳が再送信されないことを確認する。二つのテスト用オリジンに同一の合成原文を用意してキャッシュが共有されないこと、設定のキャッシュ消去後は再送信されることも確認する。代表サイトでバッチ境界をまたぐ訳語が揺れる場合は、既存の用語集や文脈設定で先に評価する。追加データの外部送信を前提にしない。
5. **Copilot の残作業。** [設定・必要権限・エラー表示](../docs/COPILOT.md) と最新の公式仕様を照合し、組織の承認を得た利用者による登録・同意で、Chrome のリダイレクト、SPA コード交換、ライセンス不足・同意拒否・期限切れ、成功時の出力隔離を確認する。通常ページ翻訳は、grounding を確実に制御できる公式機能や放出を防げる設計が確認できるまで保留する。
6. **ChatGPT サインインの残作業。** [公式クイックスタート](https://developers.openai.com/siwc/quickstart) と [登録・サインイン手順](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) を再確認し、拡張機能でサポートされるコールバックとアカウント利用条件を確かめる。ローカル補助プロセスが必要なら、個人用の最小変更という要件との兼ね合いを実装前に判断する。非公開セッショントークンや Cookie の流用はしない。

## 検証記録（実装コミット `889233b`）

- 関連テスト 45 件成功。全単体テスト 688 件中 685 件成功。既存の 3 失敗は `bench-fixtures`（履歴不足）、`release`（changelog 構造）、`network-surface`（生成済み wllama の通信検出）。再開時は新規失敗と区別する。
- 型チェック・lint・通常ビルド・正式 ZIP のパッケージ検査は成功。実キー・実 OAuth トークンを使った試験は行っていない。実ブラウザでの隔離やキャッシュ永続性、実 API の費用・速度・品質は未確認。
- モック計測は 16 セグメント、応答待ちを 50 ms に固定した比較で、逐次 16 呼び出し（約 412 ms）から 2 呼び出し（約 59 ms）。実サービスの実測値ではない。`bench:live` はローカルエンジン向けで、そのまま OpenAI の性能評価には使えない。
